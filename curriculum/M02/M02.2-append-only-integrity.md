# M02.2 — Append-only, duplicate, conflict và out-of-order

## Mục tiêu

Lưu lịch sử mà không làm mất hoặc âm thầm sửa evidence cũ.

## Canonical learner store

M02 dùng implementation nhỏ nhất có thể audit:

```text
data/history.jsonl
```

Mỗi dòng là một `HistoryRecord` immutable. JSONL được chọn để learner nhìn, diff và replay dễ; nó không phải quyết định rằng production sau này phải dùng file.

**Immutable snapshot (ảnh chụp bất biến)** không chỉ có nghĩa “không overwrite file”. Runtime phải deep-copy các giá trị input cần giữ. Nếu caller sửa object/pointer trong memory sau capture, history record đã tạo không được đổi theo.

## Duplicate không giống conflict

```text
same record_id + same canonical content
→ EXACT_DUPLICATE
→ idempotent / already seen

same record_id + different canonical content
→ CONFLICT
→ reject; không overwrite
```

Identity của observation cũng phải ổn định:

```text
same observation_id + same observation content
→ có thể được tham chiếu lại

same observation_id + different observation content
→ CONFLICT
→ reject; không biến evidence cũ thành evidence mới
```

Nếu một record cũ sai, không sửa dòng cũ tại chỗ. Correction phải là một record/review artifact mới có lineage rõ.

## Out-of-order hợp lệ

Một record có thể đến sau nhưng đại diện context cũ hơn:

```text
append order: t2 rồi t1
query order:  t1 rồi t2 theo as_of
```

M02 phải preserve cả hai. Không drop `t1` chỉ vì nó đến muộn. Query phải parse RFC3339 timestamp rồi so sánh thời gian thực; không dựa vào line order, `ingested_at` hay so sánh chuỗi timestamp một cách ngầm định.

## Corruption

Một dòng JSONL truncated/corrupt, timestamp invalid hoặc `input_hash` không khớp không được silently skip. Default M02 là **fail closed**:

```text
invalid history record
→ explicit integrity error
→ no partial "success" report
```

Sau này có thể thêm quarantine/recovery policy, nhưng không trước khi learner hiểu failure surface.

## Failure cases

- overwrite file thay vì append;
- shallow-copy làm snapshot đổi sau caller mutation;
- duplicate làm history count tăng;
- record conflict silently replace record cũ;
- reuse `observation_id` cho content khác;
- sort theo `ingested_at` hoặc line order thay vì parsed `as_of`;
- bỏ qua corrupt/hash-invalid line để report có vẻ thành công.

## PASS

Bạn giải thích được vì sao append-only là audit property chứ không phải chỉ là file format, vì sao snapshot phải thật sự immutable, và vì sao exact duplicate khác identity conflict.
