# M06.3 — n8n workflow chỉ đọc

## Mục tiêu

Dùng n8n cho schedule/orchestration khi Mission cần automation; deterministic validation và canonical business state vẫn là boundary riêng.

## Thực hành

Import `lab/n8n/M06-readonly-watcher.blueprint.json`, thay `subject_id` và URL bằng nguồn public được phép rồi kiểm tra URL/ToS trước khi activate schedule. Không thêm credential có write scope.

Trước khi coi workflow sẵn sàng vận hành, làm import + execution smoke theo
`lab/n8n/COMPATIBILITY.md`. JSON/node type hợp lệ không chứng minh một n8n
engine bất kỳ sẽ import và giữ nguyên semantics; ledger hiện không claim một
`tested_n8n_version` khi chưa có run thật.

Workflow phải thực sự đi qua:

```text
schedule
→ allowed source
→ GET
→ canonical Observation có observation_id
→ watcher cache chỉ để NEW / UNCHANGED / CHANGED
→ Canonical History Handoff sang Deterministic Core
→ report correlation/source
```

## Watcher cache (bộ nhớ đệm) != canonical history (lịch sử chuẩn)

Blueprint có thể dùng `$getWorkflowStaticData` để nhớ snapshot phục vụ change detection (phát hiện thay đổi). State này chỉ là **watcher cache (bộ nhớ đệm của watcher)**:

```text
n8n watcher cache
!= append-only HistoryRecord
!= replay history
!= canonical audit/business state
```

Mất watcher cache có thể làm lần chạy sau trở lại `NEW`; nó **không được** làm mất/reset canonical HistoryRecord. Node `Canonical History Handoff` chỉ validate và đánh dấu handoff contract (hợp đồng bàn giao) sang Deterministic Core; nó không persist canonical history trong n8n static data.

## Change detection phải dựa trên nội dung chính xác

JSON object có thể giữ cùng ý nghĩa nhưng đổi thứ tự key. Vì vậy blueprint chuẩn hóa response thành canonical JSON theo key order trước khi so sánh. Trạng thái `UNCHANGED` chỉ được tạo khi **exact canonical snapshot** của lần trước bằng snapshot hiện tại.

`content_fingerprint` chỉ là dấu vân tay chẩn đoán để đọc log; nó **không** quyết định equality. Blueprint cũng giới hạn kích thước snapshot cache và fail closed bằng `SOURCE_TOO_LARGE_FOR_SAFE_CHANGE_DETECTION` thay vì lưu static data không giới hạn.

```text
fingerprint equal
!= proof content equal
exact canonical snapshot equal
→ UNCHANGED
```

Chạy thủ công tối thiểu hai lần trước khi bật schedule. Lần thứ hai với cùng nội dung phải ra `UNCHANGED`; khi nội dung đổi phải ra `CHANGED`. Hãy thử thêm một case chỉ đổi thứ tự key của cùng JSON object: kết quả vẫn phải là `UNCHANGED`. Kiểm tra output có `observation_id`, `subject_id`, `source_url`, `observed_at`, `correlation_id` và `canonical_history_handoff=REQUIRED`.

## Continuity Gate (cổng liên tục của learner Bot)

Observation do watcher tạo phải đi vào **cùng canonical evidence/history path** mà learner Bot đã xây từ M00–M02. Không tạo một kho history riêng chỉ vì n8n dễ lưu static data.

Lưu Integration Evidence theo `starter-kits/CONTINUITY-CHECKPOINT.md`, gồm Bot version/commit, previous artifact refs, adapter entrypoint và state ownership.

## Failure cases (các ca lỗi)

- POST/PUT/PATCH/DELETE hoặc host ngoài allowlist;
- output n8n không map về canonical Observation có `observation_id`;
- dùng n8n static data làm canonical history;
- dùng fingerprint đơn lẻ để quyết định `UNCHANGED`;
- JSON cùng nghĩa nhưng khác key order bị báo `CHANGED`;
- response quá lớn vẫn âm thầm nhét vào watcher cache;
- retry tạo observation mơ hồ hoặc mất correlation;
- adapter tạo ontology/history riêng không nối M02;
- coi content fingerprint/change state là business truth.
