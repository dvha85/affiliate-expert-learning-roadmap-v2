# M04.3 — AI eval và Safe Profile

## Mục tiêu

Đánh giá hallucination, stale evidence, write request và conflict; M04 không cho write tool.

## Safe Profile tối thiểu

M04 chỉ nhận canonical context vào và trả AdvisorOutput. Không credential có
write scope, không browser action, không mutation state và không prompt nào
được quyền sửa Tool Registry. Provider/model có thể thay, nhưng profile này
không đổi:

```text
allow: summarize, compare, state uncertainty, advise
deny: write tool, execute action, invent evidence, approve itself
```

## Thực hành có hướng dẫn

1. Chạy offline eval/runtime trước để biết expected contract không phụ thuộc
   provider.
2. Chọn tối thiểu bốn test: grounded answer, hallucinated ID, stale evidence,
   và prompt xin write action. Dự đoán expected state/reason trước mỗi run.
3. Nếu thử LLM thật, log model/version, prompt template hash, context IDs và
   raw output theo quy định privacy; sau đó map qua deterministic validator.
4. Một output fail phải thành test/failure evidence, không được “sửa prompt
   đến khi qua” rồi bỏ mất case.

## Kết nối với Bot và artifact

Advisor là adapter đọc HistoryRecord/Outcome của Bot liên tục từ M02–M03. Lưu
adapter entrypoint, version/commit và exact input/output IDs theo
`CONTINUITY-CHECKPOINT.md`; `lab/mission-runtime` chỉ là oracle để đối chiếu.

## Explain-back

Hãy nói được lý do deterministic evaluator có quyền từ chối một model output
hay: nó kiểm contract/provenance, không đánh giá văn phong. CI xanh chứng minh
Capability, không biến LLM response thành Reality hoặc Operated proof.

## Failure cases

- output không map vào contract, hallucinate evidence hoặc che unknown;
- provider/tool success bị coi là trusted truth;
- request write hoặc policy update lọt qua Safe Profile;
- mất model/prompt/context version và correlation cần audit.

## PASS

Bạn tự chạy eval/runtime tương ứng, giải thích được failure case và lưu operated evidence theo starter của Mission.
