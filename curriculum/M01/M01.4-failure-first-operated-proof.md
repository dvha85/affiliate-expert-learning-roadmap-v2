# M01.4 — Failure-first verification và operated proof

## Mục tiêu

Chứng minh M01 không chỉ “có code chạy”, mà learner đã vận hành, kiểm tra failure cases và nối Bot với reality boundary từ M00.

## Ba lớp PASS

### Capability — Bot làm đúng contract kỹ thuật

Chạy:

```bash
cd lab/affiliate-bot
go test ./...
go vet ./...
go run ./cmd/bot
```

`go test` phải chạy cả executable eval pack tại `evals/M01-deterministic-bot/cases.json`.

### Reality — hiểu boundary của evidence thật

Dùng M00 Evidence Packet/DecisionPacket để xác định field nào **thực sự quan sát được** cho M01. Không fabricate `price`, `commission_rate`, currency hay identity để ép Bot ra ranking.

Nếu evidence thật chưa đủ field, một kết quả trung thực có thể là:

```text
GET_MORE_DATA
```

Đó không phải Mission failure nếu learner chỉ ra đúng field còn thiếu và next measurement.

### Operated — learner đã tự chạy và explain-back

Dùng template `starter-kits/M01-deterministic-bot/M01-OPERATED-EVIDENCE-TEMPLATE.md` và lưu bản cá nhân dưới `learner/M01/` (đã được `.gitignore` loại khỏi repo).

Ghi tối thiểu:

- command đã chạy;
- predicted result trước khi chạy;
- observed result;
- một failure case đã kiểm tra;
- M00 reality boundary;
- baseline limitation;
- next measurement.

## Failure-first rule

Một test tốt phải có khả năng FAIL khi invariant bị phá. Không chấp nhận test chỉ chạy code mà không assert behavior quan trọng.

Các invariant tối thiểu của M01:

```text
same input + same formula_version → same output
0 != missing
conflict precedence is preserved
real evidence != RECOMMEND
RANK_SCENARIO != Approval != Execution
```

## Mission PASS

M01 PASS khi **Capability + Reality + Operated** đều có evidence. PASS không trao quyền tự động hành động; M02 mới bắt đầu xây history/replay đáng tin cậy.
